# Deploying ProcureAI

The app is two pieces deployed to two hosts:

| Piece | Host | Why |
| --- | --- | --- |
| **Frontend** (React + Vite SPA) | **Vercel** | Static build, instant CDN |
| **Backend** (FastAPI) + **Postgres** | **Render** | Long-running server for AI extraction / supplier-search background jobs that serverless can't run; managed Postgres replaces the local SQLite file |

> **Why not all on Vercel?** The backend uses a real database, writes uploaded
> plan PDFs to disk, and runs background extraction/search jobs *after* sending
> the HTTP response. Vercel's serverless functions are ephemeral (no persistent
> filesystem) and freeze once they respond, so the backend needs a normal
> long-lived host. Render (or Railway / Fly.io) is that host.

Deploy the **backend first** so you have its URL when configuring the frontend.

---

## 1. Backend + database → Render

The repo ships a [`render.yaml`](render.yaml) Blueprint that provisions the web
service **and** a managed Postgres database in one shot.

1. Push this repo to GitHub (already done if you're reading this from it).
2. Go to <https://dashboard.render.com> → **New** → **Blueprint** → select this repo.
3. Render reads `render.yaml`, shows the `procureai-api` service + `procureai-db`
   database, and asks you to fill the secret env vars (`sync: false`). For a first
   deploy you can leave the optional integration keys blank — the app runs with
   clearly-flagged **mock** AI extraction / supplier search until you add them.
   - `PROCUREAI_CORS_ORIGINS` — leave blank for now; set it in step 3.
4. Click **Apply**. Render installs deps, runs `alembic upgrade head`, then starts
   uvicorn. When it's live you'll get a URL like `https://procureai-api.onrender.com`.
5. Verify: open `https://procureai-api.onrender.com/health` → `{"status":"ok"}`.

### Required env vars (set automatically or in the dashboard)

| Var | Source |
| --- | --- |
| `PROCUREAI_DATABASE_URL` | auto-injected from the Render Postgres |
| `PROCUREAI_JWT_SECRET` | auto-generated by Render |
| `PROCUREAI_CORS_ORIGINS` | **you set this** — JSON array, e.g. `["https://your-app.vercel.app"]` |

### Optional integrations (blank ⇒ mock / log-only)

| Var | Enables |
| --- | --- |
| `PROCUREAI_OPENAI_API_KEY` | real GPT-4.1 plan/BOM extraction |
| `PROCUREAI_GOOGLE_MAPS_API_KEY` | real supplier discovery (Geocoding + Places) |
| `PROCUREAI_GMAIL_*` | real RFQ email send / quote ingest |

### A note on uploaded files

The free plan has no persistent disk, so **extracted BOM data persists in
Postgres** but the **raw uploaded PDFs are lost on each redeploy** (preview /
re-analyze stop working for old uploads). To keep the files, upgrade the service
to a paid plan and attach a disk — the exact two-step change is documented inline
at the bottom of [`render.yaml`](render.yaml).

## 2. Frontend → Vercel

1. Go to <https://vercel.com/new> → import this repo.
2. Vercel auto-detects Vite via [`vercel.json`](vercel.json) (build `npm run build`,
   output `dist`). Leave the defaults.
3. Add **one** Environment Variable:
   - `VITE_API_URL` = your Render backend URL (e.g. `https://procureai-api.onrender.com`)
     — **no trailing slash**.
4. Deploy. You'll get a URL like `https://your-app.vercel.app`.

> `VITE_API_URL` is read at **build time** ([src/api.ts](src/api.ts)). If you change
> it later, trigger a redeploy so the new value is baked in.

---

## 3. Connect the two (CORS)

Back in Render, set `PROCUREAI_CORS_ORIGINS` to a JSON array containing your
Vercel URL and save (this redeploys the backend):

```
["https://your-app.vercel.app"]
```

Include every origin you'll hit the API from — add your custom domain and/or
Vercel preview URLs as additional array entries if needed.

That's it. Visit the Vercel URL, register an account, and the frontend will talk
to the Render backend.

## Local development (unchanged)

```bash
# backend (defaults to zero-config SQLite; optional local Postgres via docker compose)
cd backend && pip install -r requirements.txt && uvicorn app.main:app --reload

# frontend (proxies to http://localhost:8000 by default)
npm install && npm run dev
```
